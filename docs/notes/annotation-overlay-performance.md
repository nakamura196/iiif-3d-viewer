# 画像の上の注釈の印を軽く描く（canvas と DOM の描き分け）

## 2026-10-16

### 何をしたか

注釈が数万件ある画像で、拡大・縮小が重かった。印を 1 件ずつ DOM の要素で描いていたため。
見えている範囲の印の数で、描き方を切り替えるようにした（PR #171、da9fc2b）。

- 見えている範囲の印が 500 個以下（`DOM_MARK_LIMIT`）なら、これまでどおり DOM の印で描く。
  マウスを乗せると注釈名が出て、押すと選べる
- 500 個を超えたら、見えている範囲を 1 枚の canvas にまとめて描く。
  画面の画素の細かさ（devicePixelRatio）に合わせるので、拡大してもぼやけない
- canvas の間も、押した所にある一番小さい印を選ぶ。動かさずに押したときだけ選び、
  ドラッグは画像の移動のまま
- 選んだ印は DOM で canvas の上に重ねる
- 箱が大きいときは canvas の線を 2px にして、DOM の印と太さを揃えた。
  切り替わりの瞬間に線の太さが変わって見えないように
- 注釈 2 万件の資料では、等倍から約 15 倍までが canvas、それより拡大すると DOM になる

場所: `overlays/AnnotationOverlay.tsx`（`AnnotationCanvas`）、
`overlays/annotationMarks.ts`（見えている範囲の計算と当たり判定、テスト付き）。
拡大率の情報（`stage`）は `displays/ImageView.tsx` から `overlays/types.ts` 経由で渡す。

### 測り方

開発モード（`npm run dev`）のブラウザで、ユースケース `suikeichuzu-annotations`
（水経注図、注釈 21,245 件）を開き、拡大を 1 段ずつ進めて、1 段あたりの時間を見た。

### 実測

| | 拡大 1 段あたり |
|---|---|
| 変更前（21,243 個の印がすべて DOM） | 約 330ms |
| 変更後 | ほとんどの段で 4〜15ms |

- canvas の描画そのものは、2 万件で 6ms 以下
- 拡大し始めの 1〜2 段だけ 40〜100ms かかった。タイル画像の読み込みと重なっている時間で、
  そのうち注釈の描画は 6ms 以下だった

### 引き換えに失ったこと

- canvas で描いている間は、印にマウスを乗せても注釈名が出ない
- 印の中に本文を表示する注釈（painted）は、canvas の間は枠だけになる

どちらも、拡大して印が 500 個以下になれば元に戻る。

### 途中で分かったこと

- worktree を新しい main に載せ直したら `npm run gen` を流す。
  生成物が古いままだと、core の export が見つからず tsc が落ちる

### 確かめたこと

- tsc / eslint / vitest（661 件）が通る
- ブラウザで、縮小時の canvas 表示、印を押して選べること、ドラッグで選ばれないこと、
  拡大で DOM の印に戻ることを目で確認した

### 確かめていないこと（限界）

- 本番ビルドでの時間は測っていない。数字はすべて開発モード
- 測ったのは水経注図 1 点だけ。印の大きさの分布が違う資料（小さな印が密集する資料など）では、
  500 個の閾値が適切かは見ていない
- 時間はブラウザで目視した値で、同じ条件で繰り返し測った平均ではない
