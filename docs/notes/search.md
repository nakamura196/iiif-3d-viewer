# コレクション・キュレーションの検索画面

## 2026-10-13

### 何をしたか

`/search?u=<URL>` を足した。IIIF のコレクションか、キュレーション（CODH の Curation API）を読み、
メタデータのファセットと語句で絞り込める一覧にする。読み込みと集計はすべてブラウザの中で行う。
絞り込みの状態は URL（`q=`、`f=<項目>:<値>`）に残るので、そのまま共有できる。
項目を押すとビューアで開く（キュレーションは `pos=` で member を指し、領域に枠が出る）。

手本は ArchiveBase の IIIF キュレーション検索（https://ab.ldas.jp/en/tools/icc）。
ただし向こうはコレクションを入れるとマニフェストの一覧を出すだけで、メタデータでは絞り込めない。

- キュレーション: member ごとに 1 項目。member の `metadata` をそのまま使う。
  サムネイルは、元のマニフェストの Canvas の画像サービスから、`#xywh=` の領域を切り出して作る
- コレクション: マニフェストごとに 1 項目。コレクションのファイルには `metadata` が無いことが多いので、
  各マニフェストを取ってきて、その `metadata` を使う。入れ子のコレクションは 2 段までたどる

### 構成（機能が増えることを前提にした）

- `packages/iiif-viewer/src/core/features/search/`（React に依存しない）
  - `readers/`: 入力の種類ごとの「読み手」。`accepts`（読めるか）と `read`（項目の並びにする）を持つ。
    新しい種類は読み手を 1 つ書いて `readers/index.ts` の一覧に足す
  - `facets.ts`: 絞り込みと集計。項目の並び（`SearchItem`）だけを見る
  - `metadata.ts`・`thumbnails.ts`・`json.ts`: メタデータの整形、小さな画像の URL、参照先の取得
  - 項目は「開く先」を `target: { content, pos? }` で持つ。画面はこれをビューアの引数にするだけ
- `src/components/search/`: 画面の部品（入力欄・ファセット・選択中の条件・結果の並び）と、
  状態（`useSearchState`、URL と対応）・読み込み（`useSearchSource`）
- メタデータの言語の選び方は「この資料について」（`about.ts`）、HTML の外し方は注釈（`temporal.ts`）の
  既存の処理を使った（同じ名前の関数を新しく書きかけて、型の検査で重複に気づいた）

### 却下した案

- **ArchiveBase の検索部品をそのまま持ってくる**: Elastic の Search UI と ArchiveBase 専用の部品に
  頼っていて、Kasane に入れると依存が増える。絞り込みは数十行で書けるので、自前にした
- **マニフェスト 1 冊も受ける**（Canvas ごとに項目にする）: ビューアに「何枚目を開く」の引数が無く、
  どの項目を押しても同じ所が開く。対象外にした
- **結果から比較画面（`/compare`）に渡す**: Kasane の比較は「1 つのマニフェストの中の Choice の候補どうし」で、
  別々の項目を並べる作りではない。今回は入れていない

### 途中で分かったこと

- **国立国会図書館の画像サーバは、「枠に収める」大きさの指定（`!240,240`）に 500 を返す。**
  `240,` や `,240` は通る。サムネイルは長い辺だけを指定し、元より大きくは頼まない形にした
  （Image API 3 は拡大に `^` が要る）
- **e-codices は、同時に 6 件以上頼むと 503 を返す。** そのとき CORS の見出しが付かないので、
  ブラウザからは 503 ではなく通信エラーに見える。curl で 16 件を同時に頼むと 11 件が 503
- 同時 6 件・取り直し無しでは、214 冊中 172 冊が読めなかった。同時 4 件・取り直し 3 回（待ち 0.5・1.5・4.5 秒）で 3 冊、
  取り直し 4 回にして 0 冊になった。読み込みに約 40 秒かかる
- 画面の状態を「最初の 1 回だけ URL から読む」作りにしていたため、同じ画面の中で別の URL を開くと
  入力欄のまま残った。開く操作を状態の側に持たせ、ブラウザの「戻る」でも読み直すようにした

### 測り方と結果

- 単体テスト: 11 件（CODH のサンプルと保存済みの 2 冊、手で作ったコレクション、取り直し、ファセットの件数）。全体で 299 件通過
- ブラウザ（開発用サーバ）:
  - 江戸の花見（顔 121 点、https://nakamura196.github.io/ndl-face-finder/curations/works/edonohanami.json ）:
    29 冊を読み、121 件。ファセットは年・年代・性別・検出器。「性別: 女性」で 71 件。押すと `pos=8` で開き、顔に枠が出た
  - e-codices ボドメール文庫（https://www.e-codices.unifr.ch/metadata/iiif/collection/fmb.json 、Presentation 2、214 冊）:
    214 冊すべて読めた。ファセットは Document Type・Material・Text Language・Century など

### 確かめていないこと（限界）

- 数百冊を超えるコレクションでの速さ。読み終わるまで一覧が出ない（読めた分から出す作りにはしていない）
- 値の多いファセット（日付・番号など）は、件数の多い順に並ぶだけ。範囲での絞り込みや並べ替えは無い
- Timeline API 版のキュレーション（`cs:Canvas`）は読まない（ビューアと同じ）
