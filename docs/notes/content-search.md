# 文字の検索（IIIF Content Search API）と Text Granularity

## 2026-10-15

### 何をしたか

右パネルに「文字の検索」タブを足した。マニフェストの `service` に検索の窓口（Content Search API 2.0 の `SearchService2`、
1.0 の `SearchService1`、0.9 の古い書き方）があるときだけ出る。語を入れると窓口に問い合わせ、当たりを前後の文と一緒に一覧にし、
画像の上にも枠を出す。押すとそのページへ移り、当たった所へ寄る。候補語の窓口（`AutoCompleteService2` / `1`）があれば、入力中に候補を出す。
`?tab=contentSearch&q=<語>` で開くと、探した状態で開く（「この検索のリンクをコピー」でこの URL を作る）。

あわせて、Text Granularity 拡張（`textGranularity`: page / block / paragraph / line / word / glyph）を読むようにした。

- 検索の当たりに単位が書いてあれば、検索タブで単位ごとに絞り込める
- 注釈タブでも、単位を札として出す。単位が 2 種類以上あれば絞り込みのボタンを出し、画像の上の枠も同じ単位に絞る
- ブラウザ内の OCR（推論タブ）は、前から行に `textGranularity: "line"` を付けている。外の資料と同じ決まりで扱える

構成:

- `packages/iiif-viewer/src/core/features/contentSearch/`（React に依存しない）: 窓口を見つける・URL を作る・
  1.0 と 2.0 の応答をならして「当たり」（Canvas・矩形・当たった語・前後の文・単位）の並びにする・続きのページをたどる・
  画像の上の印にする AnnotationPage を作る
- `react/panels/ContentSearchPanel.tsx`: タブ。当たりは推論の結果と同じ「手元の注釈」（`localAnnotationPagesAtom`）に入れるので、
  枠を描く部品は新しく作っていない
- `react/displays/PagedDisplay.tsx`: 見開きの各ページにも重ね表示を載せるようにした（下の「途中で分かったこと」）

  ページ送りの打ち切り、同じ URL への循環）。全体で 594 件通過（main の #149 を取り込んだあと）

  - 1.0: MDZ の実物に `?q=der` で開く

### 却下した案・決めたこと

- **2.0 の公開の窓口を探して試す**: 2026-10-15 に探したが、実際に動いている公開の資料は見つからなかった（Archipelago・djiiif が対応をうたう）。
  2.0 は仕様の例に沿って手で書いた応答で試した。実物が見つかったら、ここに足す
- **手元の注釈（マニフェストの注釈・推論の OCR の結果）も同じ検索欄で探す**: 便利だが作りが別物で PR が大きくなるので、次の PR に回した
- **語 1 つに寄るとき、前後の行が見える広さまで囲みを広げる**: 移動の仕組みが寄せた範囲を黄色く囲むため、大きな黄色い四角が出て見づらかった。
  当たった語の矩形そのものを渡す（拡大の上限があるので寄りすぎない）
- **検索語を URL に書き込む**: 埋め込み（`<iiif-viewer>`）では、置いた側のページの URL を書き換えてしまう。URL は読むだけにし、
  共有したいときは「リンクをコピー」で作る
- **`motivation` などで絞る引数を窓口に送る**: 窓口ごとの対応がまちまちなので、`q` だけを送る

### 途中で分かったこと

- **Presentation 2 のマニフェストを公式ライブラリ（@iiif/parser の upgrader）で直しても、検索の窓口の記述は残る。**
  ただし `@id` `@type` のまま残る（MDZ は `@type` も無く、`profile` だけで見分ける）。窓口は両方の書き方で読む
- **2.0 の窓口には `profile` が無い。** `type: "SearchService2"` で見分ける（manifesto の PR #191 でも同じ指摘）
- **1.0 の候補語の応答で、語の検索 URL のキーが仕様（`url`）と違う窓口がある**（Wellcome は `search`）。Kasane は語だけを使うので影響しない
- **件数を返さない窓口がある。** MDZ は当たりが少ないとき `within.total` を付けない。その場合は集めた件数を全体の件数として出す
- **見開きの表示では、画像の上の重ね表示が描かれていなかった**（マニフェストの注釈も同じ）。見開きは画像を並べただけで、
  重ね表示の層を持っていなかった。検索の資料はほぼ本（見開き）なので、各ページの画像の矩形を毎フレーム測り、その上に層を載せた
- **入力欄に候補語の一覧（`datalist`）を付けると、入力欄の役割が searchbox から combobox に変わる。** ブラウザの試験で役割から探すと見失う
- **開発用サーバでは画面が 2 回組み立て直されるため**、タブを閉じたときに検索を止める作りにすると、`?q=` で始めた検索が止まったままになった。
  タブを閉じても検索は止めず、古い検索の応答が新しい結果を上書きしないよう、検索ごとの番号で見分ける

### 確かめていないこと

- 2.0 の実物の窓口（上記）
- 検索結果を Range や Canvas 単位の窓口（Canvas の `service` に書かれた検索）で絞ること。今はマニフェストの窓口だけを見る
- 画像の上の枠を押したときに、検索タブの一覧の同じ当たりへ移ること（選ばれた状態は共有しているので、一覧では色が変わる）
