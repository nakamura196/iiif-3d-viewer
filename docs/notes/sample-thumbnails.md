# サンプルとユースケースのサムネイル

## 2026-10-13

### 何をしたか

トップの入力欄の下（ユースケース 5 件）と `/samples`（16 件）に、サムネイルを付けた。
文字だけの一覧では「開くと何ができるか」が伝わらないため。

サムネイルは資料の画像ではなく、**Kasane で開いたときの画面**を撮ったものにした。
注釈の枠・文字起こしの欄・比較の左右表示・レイヤーの一覧が写るので、機能の違いが見て分かる。
資料の画像（マニフェストの `thumbnail` や最初の Canvas）では、音声・動画・3D に絵が無く、
注釈や比較があることも伝わらない。

- 撮影: `scripts/capture-thumbnails.mjs`。本番（kasane.ldas.jp）の `/ja/viewer` を 1280×841 で開き、
  上端のヘッダー 41 px を除いた 1280×800 を撮り、幅 640 の WebP（品質 72）にする
- 置き場所: `public/thumbnails/{samples,usecases}/<id>.webp`。21 枚で 328 KB（1 枚 2〜30 KB）
- 一覧の定義（`src/lib/samples.ts`・`usecases.ts`）を、スクリプトから直接読む。
  Node 25 は TypeScript の型を自分で取り除けるので、足りない `@/` の別名と拡張子の補完だけを
  `scripts/lib/ts-hooks.mjs` で足した。一覧を二重に持たずに済む
- テスト `src/lib/thumbnails.test.ts`: すべてのサンプル・ユースケースに画像があるか。
  サンプルを足して撮り忘れると落ちる（`--missing` で足りない分だけ撮れる）

### 途中で分かったこと

- **Chrome の `--screenshot` だけでは、動画が真っ黒になる。** 0 秒目のコマが黒い動画が多い。
  DevTools Protocol（外からページを操作する窓口）に切り替え、撮る前に動画を長さの 1/4 まで進めて止めた。
  字幕つきの動画は字幕まで写るようになった
- `--screenshot` では、動画を再生中のページで撮影後に Chrome の終了が遅れ、失敗扱いになった
  （"Teardown watchdog expired"）。これも上の切り替えで解消
- 3D（宇宙服）はヘッドレスでも `--enable-unsafe-swiftshader` で描けた。待ち時間は 30 秒にした
- **サンプルのタブ指定が 2 件まちがっていた。** 0021（タグづけ）と 0103（朗読と注釈）が
  `tab=annotations` を指していたが、これは 3D のアノテーションのタブで、画像・音声の注釈は
  `canvasAnnotations`（注釈）・`annotationTranscript`（注釈の文字起こし）。
  サムネイルで「資料情報」のタブが写っていて気づいた。`Sample.tab` の型を `ViewerTab` にした
- ヘッドレスの Chrome は幅 500 px より狭い窓を作れない。`--window-size=390,...` の撮影では
  右が切れて見えるが、変更前の画面でも同じで、ページのはみ出しではない

### 却下した案

- 実行時にマニフェストを取ってサムネイルを出す: 一覧を開くたびに 20 件のマニフェストを取りに行くことになり、
  音声・動画・3D には絵が無い
- Playwright を開発用の依存に足す: 撮影は時々しか行わないので、手元の Chrome と
  Node 標準の WebSocket で足りた

### 確かめていないこと

- サムネイルの画面は日本語版で撮っている。英語のページでもサイドパネルの文字は日本語のまま
  （縮小しているので読めない大きさだが）
- 音声のサンプル（0002・0103）は再生バーだけの画面で、絵としては弱い

## 2026-10-14

### 地球儀のアノテーションを /samples の先頭に

本人から「3D モデルへのアノテーションが売り」との指摘を受け、石淵家地球儀のアノテーション付きの例
（`public/manifests/sample-manifest-with-annotations.json`、これまでフッターからしか行けなかった）を
サンプルに足した。/samples の分類の順も 3D を先頭にした（3D → 画像 → 音声 → 動画）。

- 開いただけの画面では、ピン（北海・イギリス・フランス）が地球儀の裏側にあって写らない。
  撮影スクリプトに、撮る前の操作（`PREPARE`）を足し、アノテーションの 1 件目を押してから撮るようにした。
  押すと視点が地名へ寄り、ピンと札が写る。説明文の「押すと視点が移る」もこれで確かめた
- アノテーションのカードは `<button>` ではなく、押せる `<div>`（`cursor-pointer`）。最初はボタンを探して空振りした

### main を取り込んだときに分かったこと

- main でサンプルが 4 件（0010・0011・0033・0229）増えていて、サムネイルのテストがその 4 件で落ちた。
  撮り忘れを防ぐ仕組みとして狙いどおり働いた。`--missing` で 4 件だけ撮った
- 同時に、スクリプトが読み込みの段階で止まった。main に入ったビューアのコードに、コンストラクタの引数に
  `public` を付ける書き方があり、Node の標準の型の取り除き（strip-only）はこれを読めない。
  フックで `stripTypeScriptTypes(..., { mode: 'transform' })` を使うようにして直した（実験的な機能なので警告が出る）。
  一覧の定義がビューア本体（`@nakamura196/iiif-viewer/core`）を読み込んでいる限り、また起きうる
- 0010 は 1 回目に白い画面で撮れた。撮り直すと写った（読み込みが 10 秒に間に合わなかった）
